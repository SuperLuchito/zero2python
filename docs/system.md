## Состояние после Issue #1

## Запуск

Нужен **Node.js >=22.13.0** со встроенным SQLite. На Node 22 этот API еще экспериментальный; использована его базовая совместимая поверхность. Для нового окружения предпочтительна актуальная LTS-версия Node. Сборка загружает существующий шрифт через `next/font/google`.

```bash
npm ci
npm run dev
```

Локальное обучение работает без настройки команды. Для общего прогресса скопируйте `.env.example` в `.env.local`, задайте `TEAM_INVITE_CODE` длиной не менее 16 символов и перезапустите сервер. Сгенерировать случайный код:

```bash
node -e "console.log(require('node:crypto').randomBytes(24).toString('hex'))"
```

`TEAM_DB_PATH` указывает на SQLite-файл; по умолчанию `data/private/team.sqlite`. Один и тот же сервер обслуживает всех участников. Для другого устройства нужен сетевой адрес этого сервера, а не его собственный localhost. Деплой не входит в Issue #1.

При обратном прокси задайте `APP_ORIGIN` равным внешнему origin, например `https://learn.example.org`. Origin изменяющих запросов проверяется строго; cookies получают `Secure` для HTTPS, `HttpOnly` и `SameSite=Strict`. Сервер проверяет сессию в каждом API общих данных, а не только в интерфейсе.

Хранилищу нужен постоянный локальный диск. SQLite использует WAL и транзакции; параллельные записи объединяются внутри `BEGIN IMMEDIATE`. Файл БД, `-wal` и `-shm`, приглашения, пароли и реальные результаты не попадают в Git. Резервную копию делать SQLite-совместимым способом или после остановки приложения. Архитектура не предназначена для нескольких хостов с разными дисками или временного файлового хранилища serverless.

## Вход и синхронизация

- Создание участника требует приглашения. Имя содержит 2–32 буквы/цифры, `_` или `-`; пароль — 10–128 символов. SQLite NOCASE обеспечивает нечувствительность к регистру латинских имен; кириллическое имя вводится с тем же регистром.
- Пароль хранится как scrypt-хеш с отдельной случайной солью. Случайный токен сессии хранится в HttpOnly-cookie; в БД — только его SHA-256. Сессия живет 30 дней, выход отзывает ее. Ограничены частота входа и размер запросов (64 КиБ).
- Самостоятельного восстановления пароля, управления приглашениями через UI и администрирования участников пока нет. Приглашение настраивает организатор сервера.
- Гостевой ключ `py-term.v1` сохранен. Старые `tasks` и `qotd` читаются без сброса. Новые поля книги добавляются при нормализации. Поврежденный JSON перед перезаписью сохраняется под ключом с суффиксом `.recovery`; при недоступности хранилища отображается ошибка и остается копия в памяти.
- Участник имеет отдельный браузерный ключ `py-term.user.<id>`. Вход объединяет его локальную копию с серверной; чужой гостевой прогресс автоматически не импортируется. Кнопка «Перенести мой локальный прогресс» делает явное объединение. Выход возвращает гостевой профиль.
- Изменения участника отправляются последовательно; при сбое локальные данные остаются для повторной синхронизации. Повтор — кнопкой, при возвращении к окну или появлении сети. Неизвестные задачи и синтетический пример отбрасываются сервером. Перед записью сервер сверяет идентификатор участника с сессией.
- Решенные задания при объединении не понижаются. Чтение хранится как `{value, at}`, последняя попытка теста — `{answers, at}`; для них побеждает более новая временная отметка. Тестовый балл считается из ответов и контента, а не принимается готовым числом. При работе с нескольких устройств предполагаются корректные системные часы.
- Лидерборд читает общий источник при открытии, по кнопке, при фокусе и каждые 15 секунд видимой страницы. Сортировка — число решенных задач Python по убыванию. Места при равенстве: `1, 1, 3`; внутри равного результата строки упорядочены по имени. Чтение, тесты и число уроков показаны отдельно.

## Учебный контент и границы доверия

Книга и программа университета еще не предоставлены. Нет выдуманных глав, дат открытия и университетских заданий. Проверочный фрагмент книги явно назван синтетическим; его отдельный ключ `py-term.book-demo.v1` не синхронизируется и не влияет на личную сводку/рейтинг.

После получения книги заполнить `bookParts` проверенными частями, источниками и вопросами. Чтение и тесты используют существующий интерфейс. После получения программы определить конкретные `universityPrerequisites` и подключить реальные задания с тем же условием доступа; сейчас неизвестные URL заданий не существуют и возвращают 404.

Python и проверки остаются в браузере. Ограничение уроков организует последовательность, а не скрывает клиентский контент. Результаты Python заявлены клиентом; это учебный рейтинг доверяющей друг другу команды, не защищенный экзамен. Переноса недоверенного Python в процесс сервера нет. Прежнее отсутствие ограничения времени Python остается открытым вопросом Q007.

## Проверки

```bash
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run check
npm run build
npm start
```

`npm run check` использует Node assertions и уже установленный TypeScript: доступ, миграция, подсказки/сдача, независимость чтения/тестов, объединение, равные места, вход и долговечность SQLite. Тест использует временную БД и синтетических участников.

`tests/browser.cjs` — браузерный сценарий с Playwright и установленным Chrome. Драйвер не является зависимостью приложения; установите его в отдельное временное окружение и укажите путь через `PLAYWRIGHT_MODULE`. Запускайте **только против отдельной проверочной БД**, поскольку сценарий регистрирует двух синтетических участников.

```bash
# Сервер проверки (в отдельном терминале, после npm run build):
TEAM_INVITE_CODE=synthetic-browser-invitation TEAM_DB_PATH=/tmp/zero2python-browser.sqlite npm start -- --hostname 127.0.0.1 --port 3107
# В окружении с доступным playwright и Chrome:
TEST_URL=http://127.0.0.1:3107 TEST_INVITE=synthetic-browser-invitation node tests/browser.cjs
```

Сценарий проверяет настоящий Pyodide, закрытый URL, подсказку/сдачу, запуск без зачета, ошибочное и успешное решение, перезагрузку, тест книги, две независимые браузерные сессии, рейтинг, узкий экран, клавиатуру, сетевую ошибку, повторную синхронизацию, две вкладки, недоступное localStorage и авторизацию API. Скриншоты по умолчанию сохраняются в игнорируемом `outputs/browser/`. Отдельного lint и CI в репозитории нет.

## Остаток проверки зависимостей

`npm audit` после обновления Next.js 15.5.25 и совместимого sharp показывает два связанных предупреждения: PostCSS (high) и его зависимость в Next (moderate). Next 15 закрепляет старую версию PostCSS; предлагаемое npm исправление требует перехода на Next 16.3.4. Такой переход не включен в Issue #1. Приложение не принимает пользовательский CSS; перед деплоем нужно отдельно закрыть этот долг обновления.
