# Журнал решений

Здесь фиксируются значимые технические решения и их причины. Вопросы до принятия решения находятся в [questions.md](../questions.md); задачи реализации — в GitHub Issues.

Создавать файл `NNNN-short-title.md`, когда решение влияет на архитектуру, контракты, данные или долгосрочное обслуживание. Мелкие обратимые изменения достаточно объяснить в PR.

Формат записи:

```markdown
# NNNN. Название

Дата: YYYY-MM-DD
Статус: Предложено / Принято / Отклонено / Заменено
Связи: Issue, спецификация, официальные источники

## Контекст
Проблема и действующие ограничения.

## Варианты
Реальные варианты и существенные различия.

## Решение
Выбранный вариант, причина и основание принятия.

## Последствия
Что меняется, ограничения и способы проверки.
```

Принятый выбор не переписывать задним числом. При пересмотре добавить новое решение и ссылку из замененного. Не создавать пустые записи заранее.
