# 0004. Sites, три профиля и курс по книге

Дата: 2026-09-09
Статус: Принято

## Контекст

Пользователь поручил вход по никам Lukyan, Maria, Egor, общий лидерборд, тесты по предоставленной книге и публикацию. После обсуждения ограничений GitHub Pages предложил Sites. Прежний вариант с SQLite на Node-сервере не размещается на статическом GitHub Pages.

## Решение

Сохраняем Next.js, React, TypeScript и клиентский Pyodide. Next.js экспортирует страницы; небольшой Cloudflare Worker обслуживает API и статические файлы через ASSETS. Sites управляет D1 (прогресс и сессии) и R2 (скриншоты). Отдельный Supabase не нужен. Исходники публикуются в существующий GitHub-репозиторий, рабочий сайт — в Sites.

Вход без пароля — выбор одного из трёх профилей, а не подтверждение личности. Сервер проверяет допустимый никнейм, выдаёт случайную сессию в HttpOnly cookie и определяет профиль для каждой операции по сессии. Другую запись нельзя изменить подстановкой имени в запрос прогресса, однако любой посетитель может сознательно выбрать чужой никнейм на входе. Это прямое упрощение по поручению пользователя для небольшой доверенной команды.

Запросы записи проверяют Origin. Заголовок ожидаемого профиля защищает от записи в чужой профиль при смене cookie в соседней вкладке. Рейтинг определяется только решёнными задачами Python, с местами 1, 1, 3 при равенстве. Проверки Python остаются клиентскими и не являются защитой от накрутки.

D1 — источник результатов. localStorage содержит кеш и очередь неподтверждённых записей; очередь очищается только после ответа сервера. Никнейм вкладки — sessionStorage. Черновики кода остаются локальными и разделены по профилю. Старые нескопированные результаты переносятся только в Lukyan; устаревшие ID не входят в новый курс и сохраняются в исходном сохранении. Скриншоты сохраняются через отдельный API, зачёт не принимается обычной записью progress.

Книга: Эндрю Траск, «Грокаем глубокое обучение», Питер, 2019, ISBN 978-5-4461-1334-7. 16 глав, 48 оригинальных вопросов, объяснения и пошаговые учебные схемы. Номер страницы PDF на 1 больше печатного. Сам PDF и текст книги в GitHub/Sites не публикуются. Чтение и ответы учитываются отдельно.

## Последствия

Next-сервер в продакшене не требуется; Python запускается в браузере, не в Worker API. Для полноценной локальной проверки нужен Wrangler с локальными D1/R2. GitHub Pages не используется как второе несовместимое размещение API. Доступ по ссылке и отсутствие паролей предназначены для доверенной команды; при необходимости защиты аккаунтов потребуется изменить подтверждённую модель входа.
