# 0001. Общий прогресс команды в SQLite

Дата: 2026-09-05
Статус: Принято
Связи: [Issue #1](https://github.com/SuperLuchito/zero2python/issues/1), [система](../system.md), Q008, Q012, Q014

## Контекст

Лидерборд обязан показывать реальные одинаковые результаты участникам с разных устройств. `localStorage` не выполняет это требование. Деплой не входит в задачу; платежный сервис или внешний аккаунт для хранения не задан. Материалы книги и университета ожидаются.

## Варианты

- Оставить только локальную статистику — не соответствует обязательной приемке.
- Внешняя БД/провайдер входа — требует выбора сервиса и окружения вне текущей задачи.
- SQLite и серверные маршруты существующего Next.js — достаточны для одной небольшой команды на одном сервере, не требуют новой библиотеки хранения.

## Решение

Использовать встроенный `node:sqlite` (Node >=22.13), постоянный файл, WAL и транзакционное объединение прогресса. Добавить минимальный вход: приглашение команды, имя, пароль с scrypt-хешем и отзывные серверные сессии в HttpOnly-cookie. Общие данные доступны только участникам, как прямо определено в Issue. Гостевая работа остается доступна; перенос гостевого прогресса — явное действие.

Рейтинг: по числу решенных задач Python, одинаковое число — одинаковое место (`1, 1, 3`). Пользователь подтвердил показатель и равенство мест 2026-09-05 в ходе реализации Issue #1. Чтение и тесты не получают произвольных весов.

Технический способ идентификации и хранения выбран исполнителем в рамках поручения выполнить Issue; он не является ранее подтвержденным выбором пользователя. Детали реализации и эксплуатации перечислены в [system.md](../system.md).

## Последствия

- Общий прогресс работает между независимыми браузерными сессиями; файл переживает перезапуск сервера.
- Минимальный вход перенесен в текущую задачу как необходимая часть общего лидерборда. Самостоятельное восстановление, управление участниками и окончательное окружение остаются следующими этапами.
- Нужен сервер с постоянным диском; при нескольких хостах или serverless потребуется общий внешний SQL-сервис.
- Пароли/сессии не доступны клиентскому JS. Origin, идентификаторы контента, сессия и размер запроса проверяются сервером.
- Проверка знаний по Python остается клиентской, как и до изменения. Защита от подделки результата не заявляется.
- Синтетический пример книги изолирован от общих результатов. Структура реальных материалов остается пустой.
