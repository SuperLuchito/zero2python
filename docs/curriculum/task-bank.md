## Четыре проектных брифа

### C01. Восстановить журнал маленькой лаборатории

**Когда:** после P08, с готовым синтаксически корректным вводом; обработку неверных строк добавить после P10. **Среда:** обычные структуры Python в браузере.

Команда получает последовательность синтетических событий: идентификатор устройства, целое время и числовое показание или `None`. Нужно получить сводку по устройствам: количество событий, число известных показаний, минимум и максимум известных значений. Для устройства без известных значений минимум и максимум — `None`. Дубли событий считаются отдельными наблюдениями: дедупликации в этой версии нет.

Результат проекта — функции преобразования, примеры использования и короткое объяснение выбранных структур данных. Результат упорядочен по ID устройства; исходные записи не меняются. Сначала ученик решает обработку одного устройства, затем переносит ее на несколько.

**Приемка:** пустой журнал дает пустую сводку; реальные нули сохраняются; повторные события посчитаны; суммы по группам совпадают с общим числом строк; порядок входных устройств не меняет агрегаты. Дополнительный вопрос: какие гарантии понадобятся, если позже решим удалять дубли?

### C02. Проверяемый импорт аннотаций

**Когда:** после P13–P14. **Среда:** локальный практикум либо явно поддержанные виртуальные файлы.

Дан подготовленный CSV: ID изображения, ширина и высота, координаты прямоугольника и класс. Координаты целые и полуоткрытые: `0 <= x1 < x2 <= width`, `0 <= y1 < y2 <= height`. Пустые поля и неверные прямоугольники отклоняются с номером строки и причиной. Повторяющиеся ID изображений допустимы, потому что у изображения бывает несколько объектов. Правила повторяющихся аннотаций задаются отдельно; первоначально сохраняем их.

Результат — принятые записи, журнал ошибок и сводка по классам. Проект не открывает реальные пользовательские файлы и не изменяет входной CSV. Входные примеры включают кавычки и запятые в текстовом поле, поэтому ручное разбиение по запятой недостаточно.

**Приемка:** число принятых плюс отклоненных записей совпадает с числом записей данных; проверены нулевая площадь, правая граница, неверное число и несколько объектов одного изображения; импорт не запускает обработку; повторный запуск дает тот же результат. Итоговый разбор объясняет, почему «дубликат ID» не всегда ошибка.

### C03. Качество потока кадров

**Когда:** после D04. **Среда:** подготовленный notebook с закрепленными версиями пакетов, без внешних источников данных.

Дан синтетический набор кадров разных устройств и дней: ожидаемое количество кадров, фактически полученные, число годных кадров и пропуски показаний. Сформулируйте два разных вопроса: насколько надежна доставка и насколько хороши полученные кадры. Для каждого определите числитель, знаменатель и обработку неизвестных значений. Не подменяйте один показатель другим.

Нужно подготовить паспорт данных, проверки, таблицу по устройствам и дням, два уместных графика и короткий вывод. В данных специально меняется состав устройств; общий показатель может измениться без изменения показателя внутри устройства.

**Приемка:** определения метрик видны рядом с результатом; пропуски не превращены в нули без объяснения; все итоговые числа воспроизводятся из исходника после Restart + Run All; вывод различает наблюдение и предположение о причине. Этот проект — наша подготовка к анализу данных, а не вымышленное университетское задание.

### C04. Найти утечку до обучения большой модели

**Когда:** после ML01 и вводного CV01. **Среда:** локальный notebook с закрепленным окружением; полноценный PyTorch необязателен, достаточно небольшой модели scikit-learn на готовых числовых признаках.

Синтетические кадры имеют ID ролика, признаки и целевую метку. Сравните случайное разделение по кадрам и разделение по роликам. Выберите метрики, постройте baseline, убедитесь, что предобработка обучается только на тренировочной части. Финальную тестовую часть фиксируем заранее и не используем для выбора модели или параметров; сравнение вариантов делаем на обучающей и валидационной частях.

Результат — исполняемый анализ, проверка отсутствия пересечения ID роликов, таблица результатов и объяснение ограничения эксперимента. Нельзя заранее обещать, что «правильная» оценка обязательно ниже: задача проверяет процедуру и аргументацию, а не желаемое число.

**Приемка:** baseline есть; разбиения воспроизводимы; группы не пересекаются там, где это требуется; Pipeline содержит обучаемую предобработку; финальная оценка не подбиралась под ожидаемый эффект. Связь: [рекомендации scikit-learn](https://scikit-learn.org/stable/common_pitfalls.html).

| Читаемость | Имена выражают смысл, функции разделяют понятные операции, нет скрытых зависимостей |
| Повторяемость | Другой участник может получить результат по инструкции на тех же синтетических данных |

Это рубрика обсуждения, без утвержденных баллов и влияния на лидерборд. Если проект включается в обязательную последовательность, его приемку нужно отдельно связать с существующим правилом «все задания решены»; одного автоматического сравнения конечного числа недостаточно для оценки объяснения.
