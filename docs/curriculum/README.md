Дата: 2026-09-07. Версия: 1.0, полное авторское наполнение по прямому поручению пользователя.

Курс подключён к платформе в ветке `test/graphite-course`: 24 модуля, 33 темы вместе с четырьмя проектами, 79 проверяемых заданий. Исходные шесть уроков сохранены; продолжение написано в `extended-curriculum.py`. Это авторская подготовка по Python, данным, ML и CV, а не содержание ещё не предоставленной книги или университетского курса.

Начальный маршрут: L01 → L02 → L03 → L04 → L05 → L06. Затем углубление L07–L29 с проектами после соответствующих предпосылок. Функции не требуются в первых четырёх уроках: там проверяются программы с входными переменными. Дополнительные темы P02/P03 используют функции после вводного маршрута.

## Каким должен стать выпускник

После основного Python-направления участник должен уметь:

1. Прочитать небольшую программу, предсказать ее результат и объяснить ход выполнения.
2. Перевести условие в контракт: вход, результат, допустимые значения, крайние случаи.
3. Выбрать строку, список, словарь или множество под задачу; понимать порядок, повторы, изменяемость и владение данными.
4. Разбить обработку данных на функции, отделить вычисления от ввода и вывода, пользоваться документацией.
5. Найти ошибку по traceback, воспроизвести ее на коротком примере и закрепить исправление проверкой.
6. Прочитать CSV/JSON, сохранить идентификаторы и пропуски корректно, собрать проверяемую сводку.
7. Запустить небольшой проект в воспроизводимом окружении и объяснить его устройство другому участнику команды.

Для перехода к данным добавляются массивы, таблицы, визуализация и базовые статистические рассуждения. Для перехода к ML — независимая оценка качества, разделение данных и предотвращение утечки. Это наши учебные цели, а не обещание трудоустройства или освоения языка за фиксированное число недель.

## Как писать теорию

### Одна учебная цель за один проход

Базовый ритм: ситуация → понятная модель → короткий разобранный код → самостоятельное предсказание → объяснение неожиданного результата → практика. Если для объяснения нюанса пришлось вводить три новых механизма, его место в следующем уроке.

Ориентир для первого черновика: 400–800 слов основного текста, два-три компактных примера, один полезный крайний случай. Это редакционный ориентир, не лимит, ради которого можно выкинуть важное объяснение. Большую тему делим, а не уплотняем до телеграммы. Краткость нужна внутри каждого объяснения; сам курс может быть большим.

До первого использования нужно объяснить термин и синтаксис. Нельзя проверять замыкания, пока не разобраны функции, область видимости и функции как значения. Нельзя требовать регулярное выражение только потому, что автору так короче.

### Глубина без каталога ловушек

У каждого механизма объясняем пять вещей: зачем он нужен, что делает, как читать запись, где проходит граница применимости, как проверить результат. Нестандартные случаи выбираем по практическому смыслу: пустая последовательность, нулевой результат, повтор, общая ссылка, неверная единица измерения. Загадки про кэш маленьких чисел и неопределенное поведение среды не служат проверкой понимания.

Уместно: «Значение `0` может означать отсутствие задержки; проверка `if value` потеряет это различие». Неуместно: «Python опять обманул тебя» без объяснения модели. Не называем новичка невнимательным и не превращаем ошибки в оценку его способностей.

Примеры делаем небольшими, но связанными с будущими задачами команды: показания датчика, последовательность кадров, метки, интервалы, журнал событий. Сюжет ограничиваем несколькими предложениями; для решения не нужны знания электроники, финансов или нейросетей.

### Паспорт урока

В начале рукописи: стабильный ID, предпосылки, наблюдаемый результат, новые конструкции. В конце: проверка понимания с объяснением, связанный набор задач, один-два точных источника. Время прохождения сначала помечаем как оценку автора и уточняем после пробного прохождения; сейчас численные обещания времени не нужны.

## Как строить практику

Каждый из первых шести уроков содержит четыре задания. Усложнение идет относительно изученных средств, а не по числу строк решения.

| Ступень | Что делает ученик | Что проверяем |
| --- | --- | --- |
| 1. Применить | Решает маленькую осмысленную задачу новым механизмом | Понял базовую операцию |
| 2. Различить | Выбирает между похожими вариантами, чинит смысловую ошибку | Может объяснить различие |
| 3. Соединить | Объединяет текущую тему с предыдущими | Переносит знания |
| 4. Исследовать | Учитывает крайний случай или ведет небольшое состояние | Может обосновать, почему решение работает |

Нужны и короткие задачи. Отказ от банальности не означает отказ от доступного первого шага. Задача на остаток от деления становится полезной через кольцевой буфер с отрицательным сдвигом; задача на цикл — через сброс серии после разрыва. Сложность не должна зависеть от угадывания замысла автора.

В последующих модулях чередуем написание кода, поиск контрпримера, починку чужого решения, выбор структуры данных и небольшой проект. Текстовые ответы и ревью пока проверяются автором/участниками; не обещаем существование такой автоматической проверки в приложении.

### Контракт задания

У каждой полностью готовой задачи обязательны:

- ID, тема, ступень, нужные предыдущие конструкции;
- условие без скрытых правил; типы и ограничения входа, тип результата, порядок и повторы;
- ясное поведение для пустых значений, границ и отсутствующего результата;
- заготовка, минимум один обычный и один показательный пример, если вход параметризован;
- две последовательные подсказки: сначала модель, затем структура решения;
- проверка обычных случаев, границ и целевого заблуждения;
- эталонное решение и разбор с объяснением причины ошибки.

Не запрещаем встроенную функцию ради искусственной сложности. Ограничение допустимо, если это и есть учебная цель, и оно явно названо. Не сравниваем текст решения с эталоном: несколько разных реализаций могут быть правильными.

### Что означает «освоено»

Действует принятое правило продукта: все задания урока решены, подсказки допустимы, «Сдаться» не засчитывается. Дополнительно предлагаем возвращать знакомое умение через другую задачу в следующих модулях. Это план повторения, без изменения баллов, рейтинга и правил доступа.

На первых уроках результат скрипта проверяется по переменным и заданным исходным данным. С L05 проверяются функции на нескольких независимых входах. Проверки показывают выполнение конкретного контракта; сами по себе они не доказывают понимание. Поэтому в разборе всегда есть короткий вопрос «почему» или предложение контрпримера.

## Актуальность и окружение

Первая порция использует стандартные возможности Python 3.12 и не требует сторонних пакетов, файлов, сети или `input()`. Текущий код платформы закрепляет Pyodide 0.26.4. Это не означает, что он содержит самые новые версии библиотек.

Перед выпуском каждого раздела с пакетами фиксируем фактические версии Python, NumPy и pandas именно в целевом runtime и исполняем примеры в нем. Например, правила Copy-on-Write pandas зависят от версии: текущая документация описывает включение CoW по умолчанию в pandas 3.0, что нельзя автоматически приписывать существующему Pyodide. [Документация pandas](https://pandas.pydata.org/docs/user_guide/copy_on_write.html).

Для первых уроков достаточно браузерных вычислений. Файловые уроки сначала используют подготовленные строки или виртуальные файлы с отдельным объяснением сохранения. Окружение, Git, процессы и полный PyTorch требуют отдельного локального практикума либо будущего явно выбранного механизма. Возможности Python на обычном компьютере и в браузерном WebAssembly различаются. [Ограничения Pyodide 0.26.4](https://pyodide.org/en/0.26.4/usage/wasm-constraints.html).
